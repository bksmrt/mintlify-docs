Proof can import files directly from your institution's cloud storage and turn them into evidence documents. When you import a file, Proof downloads it, extracts text, creates searchable chunks, and, for a project inside a consulting firm's engagement, matches it against open evidence slots. The supported providers are Google Drive, Microsoft OneDrive, Microsoft SharePoint, Box, and Dropbox.

Two places in the app work with cloud storage:

- **Settings › Integrations**, in the **Storage** section: the connected accounts, their status, and the provider list. An institutional admin connects and disconnects accounts here.
- A project's evidence tab: the **Import from cloud** button opens **Import from cloud storage**, which lists the connected accounts, lets you connect one, and browses and imports files.

## Supported providers

| Provider | Authentication |
| --- | --- |
| Google Drive | OAuth 2.0 |
| Microsoft OneDrive | OAuth 2.0 (Microsoft Graph) |
| Microsoft SharePoint | OAuth 2.0 (Microsoft Graph) |
| Box | OAuth 2.0 |
| Dropbox | OAuth 2.0 |

Each provider works only after your Proof operator has configured its OAuth client. In **Settings › Integrations**, a provider that is not configured reads **Not configured by your administrator yet.** and its **Connect** button is disabled. The import dialog still lists it, but connecting fails with `provider_not_configured`.

<Note>
  The **Demo Cloud Drive**, a demo provider with four sample documents, is no longer offered on the live site. If your institution connected it earlier, the connection still appears and you can disconnect it, but browsing and importing from it are refused.
</Note>

## Connect, browse, import, disconnect

<Steps>
  <Step title="Connect an account">
    In **Settings › Integrations › Storage**, an institutional admin clicks **Connect** next to a provider. From a project's evidence tab, any member can click **Import from cloud**, then **Connect** under **Connect a new account**. Proof redirects you through the provider's consent screen and back.
  </Step>
  <Step title="Browse folders and files">
    In the import dialog, select a connected account to open a folder browser. You can navigate through folders and breadcrumbs. Files that cannot be imported are listed but marked **Unsupported**.
  </Step>
  <Step title="Import a file">
    Click **Import** next to a supported file. Proof downloads the file, runs it through the same pipeline as an uploaded document, and creates an evidence document. You see **Imported to evidence**, or **Already imported** if it came in before, and the evidence tab refreshes.
  </Step>
  <Step title="Disconnect when needed">
    In **Settings › Integrations › Storage**, click **Disconnect** on the account and confirm. Disconnecting wipes the stored OAuth credentials for everyone at the institution but keeps the import history, so provenance is preserved.
  </Step>
</Steps>

## Which files can be imported

A file is importable if it is a PDF, Word (`.docx`), Excel (`.xlsx` or `.xlsm`), CSV, or another text file such as `.txt` or `.md`. Google Docs, Sheets, and Slides are exported to text or CSV during import (see [Google Drive](/storage/google-drive)).

Files that are not importable include images, archives, RTF, legacy Office formats (`.doc`, `.xls`), and PowerPoint. They still appear in the browse view, marked **Unsupported**.

## What happens after import

1. **Document creation**: Proof creates an evidence document with the file name as its title.
2. **Text extraction and chunking**: the file's content is extracted, split into chunks, and stored.
3. **Background indexing**: embeddings are generated for search. If you imported the file into a project that belongs to a consulting firm's engagement, Proof also runs evidence matching against that engagement's open slots.
4. **Idempotency**: importing the same file from the same connection a second time returns the existing document and marks it as already imported. The unique key is the combination of the connection and the provider's file ID.

## Security and data handling

- **Tokens are encrypted**: OAuth access and refresh tokens are encrypted at rest using the shared credential encryption helper. They are decrypted only when Proof needs to make an API call or refresh a token.
- **No token exposure**: API responses list connection metadata (provider name, account identity, status) but never include the actual credentials.
- **Tenant scoping**: every connection belongs to one institution. Cross-tenant access returns a 404.
- **Read-only access**: every scope Proof requests is read-only. Proof never writes to, moves, or deletes files in your storage.
