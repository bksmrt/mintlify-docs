The Proof repo is a single TypeScript monorepo with one Express server, one React SPA, and a shared package that both sides import. Use this page as a quick reference for where to look when you need to touch a new surface.

## Top-level directories

| Directory | What it holds |
| --- | --- |
| `client/` | React SPA (Vite, TypeScript, Tailwind), plus `client/fixtures/` for the redesign fixture harness |
| `server/` | Express app, API routes, domain modules, workers, schedules |
| `shared/` | Drizzle schema, Zod types, enums, and pure business rules both sides need |
| `migrations/` | Dated SQL records of schema deltas (mirrored by `scripts/post-merge-prep.cjs`) and the frozen drizzle `meta/` directory |
| `scripts/` | Check scripts, ratchets and their baselines, backfills, smoke tests, and the repo-level tests in `scripts/__tests__/` |
| `script/` | Build and seed scripts (`build.ts`, `seed-accreditors.ts`) |
| `docs/` | Repo-owned architecture notes (`docs/*.md`), area maps (`docs/areas/*.md`), and design contracts (`docs/design/*.md`) |
| `playwright/` | End-to-end Playwright specs |
| `.github/workflows/` | CI workflows: `unit-tests.yml`, `branch-hygiene.yml`, `playwright-e2e.yml` |

## Server layout

The server is organized around an entrypoint, a very large route file, shared infrastructure, domain modules, and background workers.

### Entrypoint and shared server files

| File | Purpose |
| --- | --- |
| `server/index.ts` | Express bootstrap: middleware, route registration, worker and schedule startup |
| `server/routes.ts` | Most API routes and the `registerRoutes` closure (tens of thousands of lines; search it, don't scroll it) |
| `server/*Routes.ts` | Route groups split out of `routes.ts`, such as `iciCadenceRoutes.ts`, `strategicPlanRoutes.ts`, `droRoutes.ts` |
| `server/db.ts` | Drizzle client, pool, and the `TenantClient` that sets each transaction's row scope |
| `server/storage.ts` | The data-access layer (`storage.*` getters and writers) |
| `server/static.ts` | Static asset serving (the built client) |
| `server/rowScope.ts`, `server/rowScopeMiddleware.ts`, `server/rowSecurity.ts` | Row-level security: request scope, middleware, and boot-time role and policy setup |
| `server/firmContext.ts`, `server/firmWriteBoundary.ts` | Firm membership resolution and the firm's default-deny write boundary |
| `server/auditService.ts` | Audit ledger helpers |

### Workers and schedules

Queue workers run on pg-boss. Each schedule is a pg-boss cron whose default you can override by environment variable.

| File | Purpose |
| --- | --- |
| `server/workers/parser-worker.ts`, `parserQueue.ts` | Document parsing queue |
| `server/workers/regulatory-parser-worker.ts`, `regulatoryParserQueue.ts` | Agency standards parsing queue |
| `server/workers/sis-sync-worker.ts`, `sis-writeback-worker.ts` | SIS sync and writeback |
| `server/workers/ici-recompute-worker.ts`, `iciRecomputeQueue.ts` | ICI recomputation |
| `server/workers/catalogIngestQueue.ts` | Catalog ingestion (fetch standards) |
| `server/workers/sourceMonitorSchedule.ts` | Nightly source sweep (`SOURCE_MONITOR_CRON`, default 03:00) and hourly escalation |
| `server/workers/catalogBackfillSchedule.ts` | Weekly catalog backfill (`CATALOG_BACKFILL_CRON`, default Sunday 04:00) |
| `server/workers/controlHealthSchedule.ts`, `controlHealthSweep.ts` | Daily control health sweep (`CONTROL_HEALTH_CRON`, default 04:00) |
| `server/workers/reportDeliverySchedule.ts` | Hourly scheduled-report delivery (`REPORT_DELIVERY_CRON`) |
| `server/workers/peerSnapshotSchedule.ts` | Weekly peer aggregate snapshot (`PEER_SNAPSHOT_CRON`, default Monday 05:00) |
| `server/schedulerService.ts` | The in-process hourly scheduler (source batches, freshness and catch-up sweeps) under a database lock |
| `server/platformClocks.ts` | The operator desk's view of the clocks, with Run now and Pause |

## Client layout

| Directory | Purpose |
| --- | --- |
| `client/src/pages/` | Top-level page components (one per route) |
| `client/src/components/` | Shared and domain components; `proof/` is the design kit, `register/` the one list component |
| `client/src/hooks/` | TanStack Query hooks and local state hooks, including `useEntitlements.ts` |
| `client/src/lib/` | Utilities, Proof tokens (`lib/proof/`), and query client setup |
| `client/src/modules/` | Domain client modules |
| `client/src/App.tsx` | Route declarations |
| `client/fixtures/` | Fixture pages that mount real pages over a stub (`stub.ts`), plus approval pictures under `mocks/` |

Key conventions on the client side:

- Every list renders through the one register component (`components/register/register.tsx`), following `docs/design/register-canonical.md`. Never hand-roll a list frame.
- Marks (underlines, washes, glyphs) are drawn by `components/proof/Mark.tsx` from `lib/proof/marks.ts`. The ratchet `scripts/__tests__/vl-marks.ratchet.test.ts` counts hand-rolled marks and only lets the count fall.
- The journal tab bar draws from `lib/proof/tabs.ts`; see [Visual language](/engineering/design/visual-language).

## Shared package

`shared/` is imported by both server and client through path aliases (`@shared`, `@shared/schema`). `shared/schema.ts` is the single source of truth for every table, enum, and relation. Values the browser also needs (status lists, enum sources) live in their own modules that `schema.ts` imports, such as `shared/record-states.ts` and `shared/task-kinds.ts`.

Other shared rule tables you will meet often:

| File | What it holds |
| --- | --- |
| `shared/modules.ts` | The billing module registry: which routes and pages each module gates |
| `shared/report-catalog.ts`, `shared/report-data-catalog.ts` | Every delivered report's address and read rule; the custom report's record types and fields |
| `shared/ethos-knobs.ts`, `shared/ethos-presets.ts`, `shared/ethos-ici.ts` | Ethos settings, posture values, and posture ICI weights |
| `shared/ici-default-weights.ts`, `shared/ici-cadence.ts`, `shared/requirement-first.ts`, `shared/freshness-clocks.ts` | Score family rules |
| `shared/pipeline-run.ts`, `shared/college-copies.ts` | The pipeline run ledger and the college's copies of standards |
| `shared/workspace-href.ts` | The one builder of compliance workspace addresses |
