Proof is a modular-monolith B2B SaaS platform that helps consulting firms manage accreditation and compliance for higher-education institutions across five regulatory tiers. One Express server serves a React SPA. All routes, workers, and background jobs live in the same deployable unit, partitioned by domain modules rather than microservices.

## Architecture at a glance

The server is a single Express application (`server/index.ts`) that mounts API routes from `server/routes.ts`, serves the Vite-built client, and starts pg-boss workers and schedules for parsing, SIS sync and writeback, ICI recomputation, the nightly source sweep, catalog backfill, control health, peer snapshots, and scheduled report delivery. The client is a React SPA rendered with Vite and routed with wouter, built on Tailwind CSS, Radix UI primitives (via Shadcn/ui), Framer Motion, TanStack Query, and the Proof design kit. PostgreSQL is the only database, extended with `pgvector` for embeddings and protected by row-level security on the tables that feed AI prompts.

Shared types and the Drizzle schema live in `shared/`, imported by both server and client. This keeps the runtime contract in one file: `shared/schema.ts` defines every table, enum, and relation, and `drizzle-zod` derives validators from it.

## Stack

| Layer | Technology |
| --- | --- |
| Frontend | React 18, TypeScript, Vite 5, wouter, Tailwind CSS 3, Radix UI / Shadcn/ui, Framer Motion, TanStack Query 5 |
| Backend | Express 4, TypeScript, Node.js 22.12+, pg-boss for queues and schedules |
| ORM & validation | Drizzle ORM, drizzle-zod, Zod |
| Database | PostgreSQL 16 with pgvector extension |
| Auth | Replit Auth, WorkOS |
| AI / LLM | Anthropic (Claude, primary), OpenAI, and Google Gemini through `server/modules/ai-routing`; embeddings on OpenAI |
| Payments | Stripe |
| Build tool | `tsx script/build.ts` (Vite for the client, bundled server in `dist/index.cjs`) |
| Tests | Vitest 3, Playwright |

## Request lifecycle

A typical request flows like this:

1. **Ingress**: `express()` in `server/index.ts` applies `securityHeaders`, rate limiting, and JSON parsing.
2. **Auth**: Session middleware (`express-session` with `connect-pg-simple`) populates `req.user`. SSO routes in `server/sso/` handle WorkOS and Replit Auth flows.
3. **Routing**: `registerRoutes` in `server/routes.ts` mounts domain route groups (curriculum, compliance, approvals, billing, integrations, and so on).
4. **Tenancy**: Every route resolves the caller's institution and firm scope, and `rowScopeMiddleware` sets the request's row scope for Postgres row-level security. The `bksmrt` operator role is read-only on tenant data by default; see [Tenancy and auth](/engineering/foundations/tenancy-and-auth).
5. **Module gate**: `buildModuleGateMiddleware` refuses a route whose module the tenant hasn't licensed with `402`; see [Billing and modules](/engineering/foundations/billing-and-modules).
6. **Handler**: Route handlers call domain modules under `server/modules/*`, shared helpers, or the Drizzle db client.
7. **Response**: JSON responses are shaped with Zod schemas from `shared/`. The client SPA handles routing client-side; server-side navigation targets are validated by CI.

## Key cross-cutting rules

The codebase is held together by a small set of rules that apply everywhere. Each has its own engineering page:

| Rule | What it governs | Where to read |
| --- | --- | --- |
| **Tenancy and auth** | Institution scoping, firm isolation, role matrices, the `bksmrt` operator read-only posture | [Tenancy and auth](/engineering/foundations/tenancy-and-auth) |
| **Operator write policy** | Three-bucket classification for destructive routes: platform catalog, tenant data, and enumerated recovery actions | [Tenancy and auth](/engineering/foundations/tenancy-and-auth) (policy doc: `docs/bksmrt-write-policy.md`) |
| **Approvals framework** | Dynamic Approval Framework: policy schema, resolver engine, no-code builder, and the kind registry | [Approvals framework](/engineering/foundations/approvals-framework) |
| **Design contracts** | Canonical lists, marks, decisions, and registers; every redesign surface carries a completeness contract | [Contributing workflow](/engineering/contributing/workflow) and [Proof design kit](/engineering/design/proof-kit) |
| **Database schema** | Single source of truth in `shared/schema.ts`, applied with `drizzle-kit push`, guarded by two CI schema jobs | [Database and migrations](/engineering/foundations/database-and-migrations) |
| **Module gate** | One registry (`shared/modules.ts`) decides which routes and pages each licensable module gates | [Billing and modules](/engineering/foundations/billing-and-modules) |
| **Score family** | Readiness stays inside the college; anything comparative or external is the Proof Standard; every feature states its score touch | [Score family and the ICI](/engineering/foundations/score-family) |
| **Reports** | Every report's address lives in `shared/report-catalog.ts` and every export goes through `server/reportWorkbook.ts` | [Reporting](/engineering/areas/reporting) |
