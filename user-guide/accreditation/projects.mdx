A project is where Proof organizes a piece of work from start to finish, such as an accreditation review, a compliance response, or a curriculum change. Accreditation liaisons, compliance officers, and committee members use projects to see what is due, who owns it, and what is blocking progress.

Open **Projects** in the sidebar to see the project list. Select a project to open its detail page.

## What you see

### Project list

The list shows every project you can access. Use the search field to find a project. The view button beside it switches between three views, and Proof remembers your choice on that device:

| View | Best for |
| --- | --- |
| **Table** | Sorting and comparing many projects |
| **Cards** | Scanning projects at a glance |
| **Timeline** | Seeing due dates and overlap across projects |

Click the filter icon at the right end of the search field to open **Views & filters**. Choose one or more options under each filter:

- **Status**: **Planning**, **In progress**, **On deck**, **On hold**, **Under review**, **Completed**, **Cancelled**, **Archived**
- **Type**: **Compliance**, **Curriculum**, **Faculty**, **Scheduling**, **General**
- **Risk level**: **Critical**, **High**, **Medium**, **Low**
- **Going live**: **This week**, for projects going live this week
- **Institution**, when you can see more than one

**Sort by** orders the list by **Priority**, **Name**, **Due date**, **Effective date**, **Progress**, or **ICI impact**. Save a set of filters, sort, and search under **Saved views**. Each project also shows a standing, such as **On track**, **Attention**, **Blocked**, **Not started**, or **Done**.

**Actions** holds **Export as CSV** and **Export as iCalendar (.ics)**.

### Project detail

The top of a project shows its progress and committee, plus a primary action for the next step. When your college's Ethos asks new work to name a strategic objective, the masthead also says which one the project serves, for example **Serves 3 · Grow the region's health workforce**. If you can read the alignment report, click the objective to open it. The project's owner, a committee lead, or an institutional admin can click **Change** to pick another. A project that names none reads **No objective named**, with **Name one** for those who can edit it.

The tabs below depend on the project:

| Tab | What it shows |
| --- | --- |
| **My Role** | Your assignments on this project (only if you have a role) |
| **Overview** | Summary, current phase, impact, and quick actions |
| **Related** | Linked records, when any exist |
| **Timeline** | The project's schedule, when it follows a scenario |
| **Subprojects** | Child projects rolled up into this one |
| **Tasks** | Phases and the tasks inside each phase, as a **List** or a **Board** |
| **Committee** | Committee members and their roles |
| **Policies** | Policies this project touches |
| **Deliverables** | Outputs the project produces and their review |
| **Evidence** | Evidence requests, uploaded files, and curated evidence |
| **History** | Everything that has happened on the project |
| **Review Settings** | Review options for engagement projects (owners, leads, and admins) |

The **Actions** menu groups less common actions:

- **Project**: **Project overview**, **Compliance workspace**
- **Structure**: **Link projects…**, **Manage committee members…**, **Ask for a different governance style…**, **Save phases as template…**
- **Roll-up**: **Attach to a parent…**, **Add a subproject…**, **Move to another parent…**, **Detach from parent**
- **Lifecycle**: **Cancel project…**, **Reopen project…**, **Rewind to an earlier phase…**, **Transfer ownership…**, **Delete project…**

## What you can do here

- Create a project with **Enter a project**. A compliance project is sent for approval before its work starts. See [Start an accreditation project](/user-guide/accreditation/how-to/start-a-project).
- Check the **Tasks** tab's notice. When an open gap has no task answering it, the notice reads **Work first** and names the gap. Switch between **List** and **Board** to see the tasks by status.
- Keep every task dated. A new task is born with a due date: the date you give it, or the number of days your college's Ethos sets under **A task is due** (for example 14 days). A task in a phase that has not started reads **When it opens** and is dated when the phase opens. A task with no date reads **No date**; its assignee or the project's owner or lead can click **Set a date** to date it in place, and the change goes on the project's **History**.
- Follow each gap from the **Related** tab, including its evaluation, its cause question, and any allowed delay. See [Gaps and findings](/user-guide/accreditation/gaps).
- Open the [Compliance workspace](/user-guide/accreditation/compliance-workspace) to work through standards. See [Work a standard and close gaps](/user-guide/accreditation/how-to/work-a-standard).
- Upload files, request evidence, and review matches on the **Evidence** tab. See [Add evidence and match it to standards](/user-guide/accreditation/how-to/add-and-match-evidence).
- Build the narrative for your accreditor. See [Prepare the self-study](/user-guide/accreditation/how-to/prepare-self-study).
- Clone a project to reuse its setup, or archive it when the work is done.
