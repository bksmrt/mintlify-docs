Each webhook delivery contains a JSON envelope with standard metadata and an event-specific `data` object. This page documents the envelope schema, the available event types, and example payloads.

## Envelope schema

Every POST body follows this shape:

| Field | Type | Description |
| --- | --- | --- |
| `eventId` | string | UUID that uniquely identifies this event occurrence |
| `eventType` | string | The event type (for example, `sync.run.finished`) |
| `institutionId` | string | The tenant institution the event belongs to |
| `occurredAt` | string | ISO 8601 timestamp when the event was emitted |
| `data` | object | Event-specific payload (see below) |

## Available event types

These are the event types you can pick when you add an endpoint:

| Event type | Fires when |
| --- | --- |
| `sync.run.finished` | An SIS sync run ends with status `completed` or `partial` |
| `sync.run.failed` | An SIS sync run ends with status `failed` |
| `compliance.gap.resolved` | A compliance gap resolves, whichever path closed it (see `trigger` below) |
| `project.status.changed` | Listed for subscription, but not emitted today |
| `billing.checkout_completed` | A Stripe checkout completes for the institution |
| `billing.read_only_entered` | The institution's subscription enters read-only because billing is past due |
| `*` | Wildcard: every event type, including the other billing events below |

You never subscribe to `ping`. Proof sends it to one endpoint when you click the test button on that endpoint, whatever event types the endpoint lists.

<Note>
  `project.status.changed` is accepted when you add an endpoint, but nothing in Proof emits it today. If you subscribe to it alone, you receive no deliveries.
</Note>

### Billing events delivered to wildcard subscribers

Proof emits a `billing.<kind>` event for every billing notification on an institution's subscription. Only `billing.checkout_completed` and `billing.read_only_entered` can be picked by name. An endpoint subscribed to `*` also receives these:

| Event type | Fires when |
| --- | --- |
| `billing.payment_failed` | A payment fails |
| `billing.grace_entered` | The subscription enters its grace period |
| `billing.grace_reminder` | A reminder during the grace period (`data.graceEndsAt`, `data.daysLeft`) |
| `billing.reactivated` | The subscription is active again |
| `billing.subscription_cancelled` | The subscription is cancelled |
| `billing.plan_changed`, `billing.upgrade_applied`, `billing.downgrade_scheduled`, `billing.downgrade_blocked` | The plan changes, or a change is scheduled or blocked |
| `billing.module_added` | A module is added (`data.moduleCode`) |
| `billing.module_trial_granted`, `billing.module_trial_ending`, `billing.module_trial_expired` | A promotional module term starts, nears its end, or ends |
| `billing.trial_ending_soon` | The trial is about to end |
| `billing.upcoming_invoice`, `billing.overage_invoiced`, `billing.renewal_upcoming`, `billing.credit_issued` | Invoice, renewal and credit notices |
| `billing.po_invoice_sent`, `billing.po_invoice_paid`, `billing.po_invoice_voided`, `billing.po_invoice_overdue` | A purchase-order invoice is sent, paid, voided, or overdue |
| `billing.price_lock_expiring` | A multi-year price lock is approaching its end |

Every billing event's `data` holds `subscriptionId` and `kind`, plus the metadata of that notice. Billing for a consulting firm's own subscription never produces a webhook.

## Event payloads

### `sync.run.finished` and `sync.run.failed`

Fired at the end of every SIS sync run, including preview runs. A run that ends `completed` or `partial` sends `sync.run.finished`; a run that ends `failed` sends `sync.run.failed`.

```json
{
  "eventId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "eventType": "sync.run.finished",
  "institutionId": "inst_12345678-1234-1234-1234-123456789abc",
  "occurredAt": "2024-06-15T14:32:01.000Z",
  "data": {
    "runId": "run_98765432-1234-1234-1234-123456789def",
    "connectionId": "conn_11111111-2222-3333-4444-555555555555",
    "vendorId": "sftp_csv",
    "modules": ["curriculum", "faculty"],
    "finalStatus": "completed",
    "isDryRun": false
  }
}
```

Fields:

| Field | Description |
| --- | --- |
| `runId` | The sync run identifier |
| `connectionId` | The SIS connection that ran |
| `vendorId` | The vendor identifier (for example, `sftp_csv` for the CSV feed) |
| `modules` | The modules synced in this run: `curriculum`, `faculty`, or both |
| `finalStatus` | `"completed"`, `"partial"` (some modules failed), or `"failed"` |
| `isDryRun` | `true` if this was a preview run, which writes nothing |

### `compliance.gap.resolved`

Fired when a compliance gap resolves. The `trigger` field says what closed it.

```json
{
  "eventId": "b2c3d4e5-f6a7-8901-bcde-f23456789012",
  "eventType": "compliance.gap.resolved",
  "institutionId": "inst_12345678-1234-1234-1234-123456789abc",
  "occurredAt": "2024-06-15T16:45:22.000Z",
  "data": {
    "gapId": "gap_22222222-3333-4444-5555-666666666666",
    "projectId": "proj_33333333-4444-5555-6666-777777777777",
    "standardId": "std_44444444-5555-6666-7777-888888888888",
    "trigger": "evidence_substantiated"
  }
}
```

Fields:

| Field | Description |
| --- | --- |
| `gapId` | The resolved gap identifier |
| `projectId` | The project the gap belongs to (may be `null`) |
| `standardId` | The standard the gap relates to (may be `null`) |
| `trigger` | What closed the gap: `"evidence_substantiated"` (its required evidence was shown), `"findings_resolved"` (its last open finding was resolved), or `"cause_resolved"` (someone answered Yes to the gap's cause question) |

A gap that reopens sends no event.

### `billing.checkout_completed`

Fired when a Stripe checkout session completes for an institution tenant. It also fires when the checkout is received but payment has not cleared yet; access activates once it does.

```json
{
  "eventId": "c3d4e5f6-a7b8-9012-cdef-345678901234",
  "eventType": "billing.checkout_completed",
  "institutionId": "inst_12345678-1234-1234-1234-123456789abc",
  "occurredAt": "2024-06-15T18:10:05.000Z",
  "data": {
    "subscriptionId": "sub_55555555-6666-7777-8888-999999999999",
    "kind": "checkout_completed",
    "stripeSubscriptionId": "sub_stripe_abc123",
    "planCode": "standard",
    "bandCode": "medium",
    "cadence": "annual"
  }
}
```

Fields:

| Field | Description |
| --- | --- |
| `subscriptionId` | The Proof subscription identifier |
| `kind` | The billing event kind |
| `stripeSubscriptionId` | The Stripe subscription identifier |
| `planCode` | The purchased plan code |
| `bandCode` | The tenant size band |
| `cadence` | The billing cadence (for example, `"annual"`, `"monthly"`) |

`planCode`, `bandCode`, and `cadence` can be `null` when the checkout did not carry them.

### `billing.read_only_entered`

Fired when an institution's subscription enters read-only because billing has been past due for more than 14 days. Write actions are disabled until the outstanding invoice is paid. `data.graceEndsAt` is when the grace period ended.

```json
{
  "eventId": "d4e5f6a7-b8c9-0123-defa-456789012345",
  "eventType": "billing.read_only_entered",
  "institutionId": "inst_12345678-1234-1234-1234-123456789abc",
  "occurredAt": "2024-06-15T19:00:00.000Z",
  "data": {
    "subscriptionId": "sub_55555555-6666-7777-8888-999999999999",
    "kind": "read_only_entered",
    "graceEndsAt": "2024-06-29T19:00:00.000Z"
  }
}
```

### `ping`

Queued for one endpoint when you click its send (test) button in **Settings › Webhooks**.

```json
{
  "eventId": "e5f6a7b8-c9d0-1234-efab-567890123456",
  "eventType": "ping",
  "institutionId": "inst_12345678-1234-1234-1234-123456789abc",
  "occurredAt": "2024-06-15T20:00:00.000Z",
  "data": {
    "message": "Test delivery from EduComply."
  }
}
```

## Wildcard subscription

If you subscribe to `*`, your endpoint receives every event type, including every `billing.<kind>` event and any type added later. This is useful for logging or audit pipelines, but your receiver should ignore event types it does not recognize. If you need to filter after receipt, inspect the `X-Booksmart-Event` header or the `eventType` field in the body.
